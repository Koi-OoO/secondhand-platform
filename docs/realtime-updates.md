# 实时页面更新

## 页面行为

- 商品详情、我的商品、我的收藏订阅当前可见商品的库存和状态。收到事件后只补查这些字段，不重新加载详情、不增加浏览量，不重排整个商品广场。
- 我的买入/卖出订单、订单详情、聊天订单抽屉复用已登录的通知连接，静默刷新并保留分页、表单和当前选择。正在提交操作时延后刷新。
- 聊天窗口重连或回到页面时补取当前会话，保留草稿；后台补取时尽量保持历史阅读位置。预约卡片随聊天或订单通知更新。
- 切回可见页面和连接恢复时补查。商品连接有 10 秒握手超时、25 秒心跳与无响应重连。可见页面每 30 秒做轻量补查作为兜底；隐藏页面不补查商品或订单。

## 后端边界

已有数据库需执行尚未应用的 `secondhand-platform-backend/src/main/resources/sql/2026-10-24-notification-actor.sql`，补充通知发起者快照字段；该迁移只执行一次，已应用的不要重复执行。新建空库使用的 `init.sql` 已包含这些字段，已有库不要运行删表重建脚本。

登录聊天仍用 `/ws`，游客无法连接。公开商品连接为 `/ws/products`，仅接受 `subscribe` 商品 ID 列表或 `ping`。服务端只发送 `subscribed`、`pong`、`product_changed`（商品 ID），不带用户、订单、聊天数据。

`GET /product/availability?ids=364,365` 最多查询 50 个 ID，直接读 MySQL，只返回 `id/stock/status`。不存在和删除商品统一返回库存 0、状态 4。下架、售罄状态沿用现有公开详情页的可见规则，不提供额外私有资料。

商品编辑、上下架、删除、下单扣库存、取消或拒绝订单回补库存，在事务提交后发送变更事件；回滚不发送。推送失败不改变已经提交的业务结果，补查负责恢复。直接使用数据库工具修改数据不触发业务推送，可通过切回页面或 30 秒补查看到新库存。

当前为单后端实例实现，连接数上限 256、同一来源地址最多 8 条商品连接、每连接 50 个订阅和每秒 10 条客户端消息，超限关闭并清理。实际多实例部署需要另行增加实例间广播。若前后端分离部署，可设置 `VITE_PRODUCT_WS_URL`；开发代理现有 `/ws` 规则已覆盖公开子路径。

## 验证

- `npm run test:unit`：协议、订阅替换、重连、心跳、合并刷新和其他业务单元测试。
- `npm run test:realtime`：使用独立无头 Chrome、真实 Vue 组合函数和模拟接口，验证乱序请求、焦点/可见性、订单通知、草稿/分页保留、页面卸载清理。没有 Chrome 时跳过浏览器测试；产物放在已忽略的 `target/realtime-tests`。
- 后端 Maven 测试覆盖匿名只读接口、订阅隔离、限额、事务提交/回滚时机和库存业务事件触发。

首次会话创建和首条消息共用数据库用户对唯一键及原子写入，重复打开不会覆盖消息摘要；摘要按消息 ID 保持单调更新。显式运行本机并发验收可使用 Maven 参数 `-Dconversation.flow.integration=true -Dtest=ConversationConcurrencyIntegrationTest`；它会提交独立临时测试用户和消息以覆盖真实并发，在 finally 中清理，不向实际浏览器推送。默认测试跳过该数据库验收，不需要额外迁移表结构。

手工验收：游客打开商品详情，卖家下架修改库存后上架；另一买家下单、取消。观察详情/收藏/我的商品自动变化。买卖双方分别停留订单列表，测试接单、预约和交付后的状态变化，再断网重连检查恢复。页面显示仍可能短暂落后，真实下单必须由后端校验库存与权限。
